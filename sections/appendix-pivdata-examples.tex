\section{PIVGETDATA Worked Examples (Informative)}
\label{app:pivdata-examples}

These examples show the enhanced request defined in
Section~\ref{sec:pivdata}, the OSDP~3.0 multi-part response defined in
Section~\ref{sec:pivdatar}, and the error reply defined in
Section~\ref{sec:piverror}.

In the frame exchanges below, the ACU and PD are simulated. Credential data comes from the identified
existing card captures; constructed error cases are identified separately.
These examples omit OSDP Secure Channel~3.0 for clarity. CRC detects
transmission errors. The exchanges provide neither authentication nor
confidentiality. Some source captures used credential-side secure messaging;
the examples use the data recovered after that processing.

The files under \path{worked-examples/pivdata/} contain the complete frame
exchanges, expected results, source hashes, and validation instructions.
Each example ID also appears in the data file, so the printed example can be
matched to its complete exchange. Long responses are shortened in this appendix only.

\subsection{Reading the exchanges}
Field values use hexadecimal with a \texttt{0x} prefix. Packet dumps use
space-separated hexadecimal byte pairs under \emph{Packet bytes (hex)}.
Two-byte field values are shown as numbers in the request table and in
least-significant-byte-first order in the packet bytes.

An accepted PIVGETDATA command receives ACK. The ACU then sends POLL until the
PD returns a data fragment or PIVERROR. The first data fragment has offset zero,
even when Offset in the command is nonzero. Further polls retrieve the rest
of the data in order, until the ACU has received the advertised total.
Polls during processing receive ACK. The examples use a maximum frame size
of \code{0x0080} bytes, including header and CRC; this leaves \code{0x0072} data bytes per
PIVGETDATAR fragment when no security block is present.

A whole-object read includes the object's outer tag, length, and value.
An inner-tag read includes the selected element's tag, length, and value,
and excludes the enclosing object's tag and length. Offset and Requested Length
then determine which bytes to return. Offset zero starts at the selected tag;
skipping its tag and length returns only value bytes.

The PD divides the requested data across replies. Each TLV header occurs once
in the reassembled data. Each reply has its own OSDP framing, reply identifier,
and multi-part fields; the ACU joins only the Card Data bytes.
Certificate and biometric values retain their original encoding.
Selecting the FASC-N and UUID elements individually allows the ACU to read them
regardless of their positions within the CHUID.

\subsection{TWIC NEXGEN E-Sticker: captured write, read, and erase}
\label{ex:twic-esticker-live}

This card-command trace was captured on 2026-11-11 from a NEXGEN V8 TWIC
using an Identiv SCR3500 C contact reader and PC/SC. The selected TWIC AID is
\HexBytes{A000000367200000010103}. The APDUs and responses are recorded in
\path{worked-examples/twic-esticker/trace.json}. Each response below includes
SW1 and SW2. The initial inspection returned \HexBytes{E1006282}, an
uninitialized E-Sticker. The verified sequence below starts with the empty
encoding \HexBytes{E1028000} established by the first erase.

\begin{enumerate}
  \item \textbf{Select the TWIC application.}
    Command: \HexBytes{00A4040009A00000036720000001FF}.\par
    Response: \HexBytes{612A4F0BA00000036720000001010379074F05A00000036750124E455847454E2052454C4541534520312E307F6608020203F8020280019000}.
  \item \textbf{Verify E1 is empty.}
    Command: \HexBytes{00CB3FFF035C01E1FF}.\par
    Response: \HexBytes{E10280006282}.
  \item \textbf{Write the E-Sticker.}
    Command: \HexBytes{00DB3FFF07E1058103414243}.\par
    Response: \HexBytes{9000}.
    The native E1 object contains child tag \code{0x81} with value \texttt{ABC}.
  \item \textbf{Read back the exact object.}
    Command: \HexBytes{00CB3FFF035C01E1FF}.\par
    Response: \HexBytes{E10581034142436282}.
  \item \textbf{Erase the E-Sticker.}
    Command: \HexBytes{00DB3FFF04E1028000}.\par
    Response: \HexBytes{9000}.
  \item \textbf{Verify E1 is empty again.}
    Command: \HexBytes{00CB3FFF035C01E1FF}.\par
    Response: \HexBytes{E10280006282}.
\end{enumerate}

TWIC Part~2, Sections~5.2 and~5.4 and Appendices~E--F, define the transfers,
short-read status, and empty E-Sticker encoding. Here Le is \code{0xFF};
the complete objects contain fewer than 255 bytes, and each read returns
\code{0x6282}. Under the response-length rules in
paragraph~\ref{sec:card-response-length}, PIVGETDATA
\HexBytes{A301E10000000000} returns the captured object bytes in
PIVGETDATAR: \HexBytes{E1058103414243} after writing and
\HexBytes{E1028000} after erasing. The OSDP mapping uses TWIC Data Model
\code{0x02} and the selected TWIC application, as in the E-Sticker example in
the PIVPUTDATA subsection.
